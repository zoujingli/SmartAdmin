# 任务调度

System 提供内置调度进程 `system.scheduler`，作为全站共享调度内核。它不是 `system.queue`，也不依赖 Hyperf Crontab；当前版本通过 System 自管进程扫描数据库计划并执行白名单任务。

System 负责进程、白名单任务注册、到期扫描、抢占执行和通用执行日志。业务插件负责自己的规则入口、权限、参数语义和业务校验。平台运维里的“任务管理”是调度总览和 System 内置任务管理，不代替业务插件编辑业务规则。

短时异步任务进度同样由 System 提供统一查询能力。前端公共任务进度弹窗不直接写死接口地址，而是在应用启动时通过 System 插件 `setup.ts` 注册的 provider 请求 `/system/task/status`；业务插件页面只传入 `task_id` 并复用公共弹窗。

## 启动方式

- 调度进程通过 `#[SystemProcess(default: true)]` 声明，并在 Swoole 主服务启动前注册。
- 默认随服务启动，不提供 `SYSTEM_SCHEDULER_ENABLED` 环境开关。
- 是否执行具体任务由计划状态、计划配置和业务插件自己的开关决定。

## 多实例行为

调度进程会扫描 `system_scheduled_task` 中已启用且到期的任务，并用数据库锁字段抢占。多实例部署时，多个进程可以同时扫描，但同一计划同一时间窗口只应由抢占成功的实例执行。

执行日志写入 `system_scheduled_task_log`，可在“平台运维 / 任务管理 / 执行日志”查看。

## 任务归属标准

每条计划都有归属字段：

| 字段 | 说明 |
|------|------|
| `owner_plugin` | 归属插件，例如 `system`、`material`、`project` |
| `owner_type` | 归属资源类型，例如 `system`、`material_source`、`project_app` |
| `owner_id` | 归属资源 ID；全局 System 任务使用 `0` |
| `owner_name` | 归属资源展示名 |

唯一规则是同租户、同 `owner_plugin/owner_type/owner_id/code` 只能有一条计划。删除计划使用软删除；再次保存相同归属和编码时会恢复原计划并更新配置，避免唯一索引死锁。

插件通过 `PluginScheduledTaskService` 读写计划时必须存在当前租户上下文；服务会把当前租户和 owner 一起作为查询边界。owner 字段只表达业务资源归属，不能替代租户隔离。

System 页面只允许编辑 `owner_plugin=system, owner_type=system, owner_id=0` 的内置任务。业务插件任务可以在 System 页面查看运行态和日志，但规则编辑必须回到插件自己的页面和接口。


## Queue 与 Crontab 边界

- Queue 适合高并发异步执行、削峰和重试；它不负责后台可视化周期管理。当前版本保留 `ScheduledTaskExecutorInterface`，后续需要时可以替换为队列执行器。
- Crontab 适合代码静态声明的周期任务；当前需求要求后台可编辑，所以不直接依赖 Crontab 组件。
- 外部系统 crontab 仍可用于独立运维脚本，但业务同步优先注册为 `#[ScheduledTask]` 并通过插件自己的管理入口维护规则，让权限、日志和租户上下文在后台闭环。

## 排查顺序

1. 确认计划状态为启用，`next_run_at` 已到期。
2. 确认插件自身开关或资源状态允许执行，例如 Material 数据源需启用并开启同步。
3. 查看执行日志中的 `owner_*`、`status/message/result`。
4. 检查业务插件是否启用，相关 `#[ScheduledTask]` 处理器是否在注解扫描路径内。
5. 多实例环境检查数据库连接和锁字段 `running/locked_until`。
6. 修改 Provider、注解或依赖后重启 Swoole 服务。
