# 日志与异常

## 日志体系总览 🧾

当前系统日志拆分为 `LogsActionService` 和 `LogsChangeService`：前者负责接口操作行为写入、统计、清理和实时窗口分析，后者负责业务数据变更明细查询。列表数据如需导出，由前端复用分页接口生成 xlsx。

核心分类：

- **登录日志**：登录成功/失败、请求来源
- **操作日志**：业务操作名称、请求信息、响应摘要和客户端环境
- **变更日志**：业务对象、动作、字段变化和关联操作日志
- **错误日志**：失败状态、异常说明、上下文

## 日志写入路径（实现对齐）🔍

全局请求日志由 `LogsMiddleware`、`ResponseExceptionHandler`、`AppExceptionHandler` 和 `RequestLogRecorder` 写入。请求入口输出 `onRequest`，响应结束输出 `onResponse`，真实系统异常额外输出单独的 `exception` 日志，并通过日志 extra 中的 `request_id` 与 `coroutine_id` 关联。

`onRequest` 只记录请求入口上下文，字段固定为 `method`、`path`、`query`、`client_ip`、`user_agent`、`user`、`body`。其中 `client_ip` 使用 `IP - 归属地` 格式，`user:null` 表示请求进入阶段没有从 `Authorization: Bearer xxx` 或 `token: xxx` 中解析到登录身份，不代表权限校验失败或用户不存在。

`onResponse` 只记录响应摘要，字段固定为 `http_status`、`duration`、`memory_usage`、`body`。全局请求日志不再输出 `uri`、`status`、`ip`、`ip_location`、`body_code`、`body_info`、`result`、`size` 或 `onResponse.exception`。

`body` 输出遵循预览规则：请求体或响应体超过 10KB 时整体输出 `{"...(>10KB)":"不输出日志"}`，不再解析或保留原文片段；10KB 内标准 JSON 保持原结构，只对对象字段、数组元素和长字符串做递归裁剪；对象字段、数组元素或 query 参数超过上限时追加 `"...(N)": "太多内容了"`，其中 `N` 是省略数量；10KB 内非 JSON 内容输出脱敏后的字符串，不使用 `raw` 包装。

文件下载、不可读流和未知流响应不读取内容，`onResponse.body` 输出 `null`。上传、`multipart/form-data`、`application/octet-stream`、`application/zip`、图片、音频和视频等二进制请求体不进入全局请求日志，`onRequest.body` 输出 `null`。

真实系统异常单独输出 `exception` 日志，字段固定为 `exception.class`、`exception.code`、`exception.message`、`exception.file`、`exception.line`、`exception.trace`。`BaseResponseException(code=200)` 是成功响应控制流，不写异常日志；`BaseResponseException(code!=200)` 且没有 `previous` 是业务失败，只写 `ERROR onResponse`；带 `previous` 或非标准 `Throwable` 会写 `ERROR onResponse` 与单独 `ERROR exception`。当请求上下文缺失或请求日志链路失败时，异常处理器仍会兜底输出结构化 `exception` 日志。

操作日志由 `#[Logger]`、`LoggerAspect`、`ResponseExceptionHandler`、`OperateLogRecorder` 和 `LoggerListener` 写入，补齐请求方法、路由、IP、终端信息、请求体、响应体等字段。操作日志落库仍保留独立 `ip`、`ip_location`、`response_code` 等结构化字段，便于后台筛选统计。

变更日志由模型事件监听器记录 `created/updated/deleted/force_deleted/restored`，关系授权、配置数组等模型事件不稳定的场景由对应 Service 显式追加。

## 统计与分析能力 📊

`LogsActionService` 内置以下运维分析能力：

- `getStatistics()`：按响应码/用户/业务/时间窗口统计
- `getAnalysisReport()`：按小时/星期聚合 + 错误日志样本
- `getRealtimeMetrics()`：1m/5m/15m 近实时计数、错误数、每分钟事件速率
- `LogsChangeService::getStatistics()`：按动作、模型、业务表统计变更明细
- 前端导出：复用操作日志或变更日志列表分页接口按筛选条件生成 xlsx

## 清理与归档策略 🗂️

- `/system/logs/action/clear`：按可选天数清空操作日志，并同步处理关联变更日志

建议在运维任务中明确：

- 清理窗口（例如 90 天）
- 日志表属于发布忽略表，生产侧应单独制定备份策略

## 安全与合规要求 🛡️

- 密码、Token、Secret、Key、Cookie、Authorization 等字段必须脱敏
- 大型请求体和响应体超过 10KB 时不输出原文，只输出固定占位
- 生产环境必须确认请求日志、操作日志、变更日志和异常日志都保持脱敏规则生效

## 异常响应一致性 ⚠️

所有接口应维持统一响应结构（`code/info/data/path`），确保日志统计与前端错误处理口径一致。

日志级别约定：

- `INFO`：响应体 `body.code = 200`；没有业务码时 `http_status = 200`
- `ERROR`：响应体 `body.code != 200`；没有业务码时 `http_status != 200`
- 真实系统异常额外输出结构化 `exception` 日志；全局请求日志不再使用 `WARNING`
- 响应体超过 10KB 或不可读时不输出原文；若异常对象是标准 `BaseResponseException`，日志级别仍按异常标准响应体中的 `code` 判定

## 排查建议（按优先级）✅

- 先看请求链路日志，再看业务异常与数据库执行日志
- 优先观察 `getRealtimeMetrics()` 的 5 分钟窗口错误率
- 涉及权限问题时同步核对角色节点与缓存状态
- 登录类故障优先检查登录日志与 token 生命周期
