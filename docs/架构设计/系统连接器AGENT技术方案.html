MODE 01 · OFFLINE

普通模式 + 无连接

上传材料后完成摘要、归纳、润色和候选内容生成。

  • 无需账号授权。
  • 不读取业务系统实时数据。
  • 适合一次性任务。
低风险
MODE 02 · POC

普通模式 + API / SDK

单系统、短周期、固定接口的技术验证。

  • 不承担通用工具发现。
  • 接口、身份和错误处理需自行封装。
  • 验证完成后评估 MCP 化。
验证用
MODE 03 · PRODUCT

应用模式 + MCP + OAuth

实时读取、多轮追问、Skill 和标准工具目录。

  • 用户在原系统授权页输入密码。
  • Agent 只拿授权结果，不接触密码。
  • 每次调用重新校验权限和数据范围。
当前采购方案

服务身份 + 工作流

无人值守的定时、批处理和跨系统编排。

  • 使用服务账号或工作负载身份。

独立治理

05 / Why MCP

为什么使用 MCP

MCP 适合把实时业务能力做成可发现、可复用、可治理的连接层。

VALUE 01

统一发现

客户端通过同一套协议发现工具和能力，不再为每个 Agent 单独硬编码接口。

VALUE 02

统一契约

工具输入、输出、错误、参数白名单和只读边界集中定义，便于版本演进。

VALUE 03

集中授权

OAuth、Scope、权限、租户、限流、脱敏和审计由连接层统一处理。

VALUE 04

跨客户端复用

同一个 MCP Server 可以服务 WorkBuddy、内部 Agent 和其它兼容客户端。

VALUE 05

业务解耦

业务系统保持原有 Service/API，Agent 只依赖工具契约，减少客户端定制。

VALUE 06

可运营

连接、工具、版本、调用耗时、拒绝率和撤销动作有统一的观测入口。

不需要 MCP

  • 聊天、摘要、润色和静态文件分析。
  • 单系统、一次性、固定接口的 API / SDK PoC。
  • 无人值守的内部工作流，直接使用服务身份和任务编排。

适合使用 MCP

  • 实时数据、多轮追问和多个工具协作。
  • 多个 Agent 客户端需要复用同一能力。
  • 需要统一 OAuth、Scope、租户、审计和工具治理。
  • 遗留系统已有稳定 API，需要逐步标准化接入。

07 / Request flow

一次调用链

授权只发生在原系统页面，模型上下文只接收经过策略过滤的结果。

1

提出问题

用户在普通模式或应用模式输入自然语言问题。

2

选择连接

Skill 根据任务判断是否需要实时系统数据。

3

完成授权

浏览器打开原系统 OAuth/PKCE 页面，用户自行输入账号密码。

4

发现工具

MCP 返回当前连接可用的工具、Scope 和参数约束。

5

读取事实

网关校验权限、租户、范围、参数和限流后调用业务查询。

6

返回解释

Agent 基于事实和证据回答，写请求转人工确认。

会话数据边界：密码、Refresh Token、完整用户资料和未脱敏业务数据不进入模型上下文；工具结果带 queried_at、scope、evidence 和 redactions。

输入：固定资源类型、白名单筛选、分页和日期边界；不接受字段名、SQL、脚本、任意 URL 或任意关联名。

输出：业务数据与 scope、queried_at、evidence、redactions 一起返回。

失败：身份无效返回重新授权；无权限返回拒绝；范围过大返回收敛建议；系统异常返回可重试标记。

09 / Security

安全约束

连接器不能成为权限旁路；每一层都以原系统的账号、租户和审计为准。

◈

OAuth / PKCE

账号密码只在原系统页面输入，连接器保存授权结果，不保存密码。

⌁

Scope 最小化

按连接、工具和资源范围发放 Scope；授权升级重新同意。

▣

权限再校验

每次工具调用重新验证用户、角色、租户和数据范围，缺少上下文默认拒绝。

⌑

参数与结果

输入字段白名单、分页和限流；输出脱敏并限制长度，带证据元数据。

◌

审计与撤销

记录连接、工具、范围、耗时、结果状态和撤销动作，敏感值全部脱敏。

×

写入隔离

首期不注册创建、修改、发布、删除和状态变更工具；候选内容必须回原系统人工确认。

禁止传递

密码、Refresh Token、Cookie、Authorization、数据库连接、租户全量资料和未脱敏日志。

失败策略

授权失效要求重新授权；权限不足停止调用；范围过大收敛查询；写请求返回人工确认入口。

Appendix

边界问答

用于现场说明方案取舍。

为什么不能把密码交给 Agent？

密码属于原系统登录凭证，Agent、Skill 和模型上下文都不应接触。用户在原系统 OAuth 页面完成认证，连接器只使用短期授权结果。

什么时候用普通模式？

只处理用户上传材料、摘要、润色或一次性生成时使用普通模式；需要实时数据、多轮工具调用和固定连接时使用应用模式。

什么时候可以增加写工具？

先完成只读链路、权限复用、审计和人工确认。具备幂等、审批、回滚和独立审计后，再按业务逐项评估，不能直接开放通用写工具。
